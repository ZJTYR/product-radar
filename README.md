# 拾光 · 产品情报工作台

面向产品经理的跨行业产品研究、商业分析、AI、科技与产品前沿、设计灵感与每日简报。首页按今日重点、前沿动态、产品发现与设计灵感组织；保留资料库搜索、通俗产品详情、收藏分类、统一笔记、历史快照与手机布局。

- 个人私有仓库：https://github.com/ZJTYR/product-radar
- Vercel：qyh's projects / product-radar，生产分支 main。

## 访问与数据

所有域名均要求 Vercel 登录；使用创建项目的个人账号访问。当前是单人工作台，稳定所有者为 `github:107673736`。**必须保持 Vercel Authentication = All Deployments，不能关闭或授予其他人访问。** `RADAR_OWNER_PRIVATE=true` 是部署配置检查，不是独立鉴权。未来公开或多人使用须先增加应用登录和逐用户授权。

生产数据保存在 Neon 免费套餐的 Postgres 中，功能部署不会清空收藏和历史。采用参数化查询及数据库事务。2026-10-23 从原站导入 21 条资料、2 期快照和已有偏好；个人数据与导出文件不进入 Git。

## 本地运行

需要 Node.js 24 和 npm。

```sh
npm ci
npm run dev -- --hostname 127.0.0.1 --port 5187
```

访问 http://127.0.0.1:5187/ 。未设置 DATABASE_URL 时，本地使用 `.local/radar.sqlite`；Vercel 环境禁止退回本地文件数据库。首次初始化只加载注明原始日期的种子资料，不冒充今日简报。

```sh
npm run lint
npm run check
```

生产 DATABASE_URL 由 Neon/Vercel 注入，RADAR_OWNER_PRIVATE 和 RADAR_OWNER_EMAIL 只在服务端配置。`.env.example` 仅列变量名称。不上传真实 .env、.vercel、数据库或私有导出文件。

## 按兴趣浏览

首页“先看懂一个产品”固定保留：优先展示本期未读、未收藏、未划走的产品；本期候选不足时从资料库按真实收录时间补位，标注“资料库精选”和收录日期。阅读或收藏后当前卡片继续保留，检查新简报或再次访问时选择下一条；划走后立即补位。全部候选耗尽时显示真实空状态与全部产品入口；阅读或偏好读取失败时提示重试，不把失败描述为已看完。

首页“产品发现”默认展示8张卡片，桌面4列×2行，手机随屏幕调整列数；覆盖跨行业产品，并提供GitHub高关注筛选。点击“不感兴趣”保存成功后只替换当前卡位，其他卡片和滚动位置保持稳定；“感兴趣并收藏”保留当前卡片并显示收藏状态。可撤销并恢复原卡；候选不足时显示真实提示，不循环旧内容凑数。

成功打开产品详情后自动记录已看，当前卡片继续保留，下一批、刷新或再次访问时默认不重复推荐同一条介绍。已看只用于去重，不作为负反馈，也不自动增加兴趣权重；仅打开页面或关闭弹窗不算产品阅读。已看资料仍可通过搜索、全部产品、历史和收藏查阅，无需额外的“看过了，换一条”按钮。

“为你推荐”从已有资料库逐条补齐内容，桌面可点按钮或聚焦卡片使用左右方向键，手机可左划“不感兴趣”、右划“感兴趣并收藏”。保存成功后再切换；没有未处理内容时显示真实空状态，等每日采集补充，不在每次划动时重新研究或制造新内容。

反馈持久保存在个人数据库中。推荐按主题、标签、产品类型、可识别来源及公众号 `__biz` 账号信号排序，每四个选择留出探索机会；仅隐藏明确处理过的条目，不因一次划走封禁整个行业或作者。未知作者不猜测，浏览停留时间不采集。现有收藏也作为积极信号，同一条内容不重复计权。

详情底部不再显示独立的收藏备注表单；详情收藏按钮旁和“我的收藏”卡片底部提供分类入口，可选择已有分类或输入新分类。分类保存只更新分类，遇到跨页面冲突时提示重新选择，不覆盖备注和笔记。所有文字记录统一使用“写想法”和“我的笔记”。

“感兴趣”自动加入收藏并保留原有分类和备注；“不感兴趣”不删除历史简报及已有收藏。可撤销最近选择，或在“已划走”中恢复。撤销只移除该次操作自动建立且未被后续编辑的收藏；其他页面已修改反馈时拒绝覆盖。反馈和收藏通过数据库事务版本协调，支持多个标签页与 Vercel 实例。

本地端到端验收可设置 `DATABASE_URL='' RADAR_LOCAL_DB_PATH=/absolute/private/test.sqlite` 隔离测试数据；默认仍使用 `.local/radar.sqlite`，线上没有 `DATABASE_URL` 时仍会拒绝回退到文件数据库。

页面、关键词、筛选条件、历史日期和打开的详情保存在 URL 中，支持复制直达、刷新恢复与浏览器返回/前进。关闭详情时恢复原列表和滚动位置；历史直达只使用对应日期的简报快照，不混入最新版本。“全部产品”和设计资料支持分类与排序；首页的 GitHub 数据核对入口位于“更多”。

## 前沿动态与简报阅读

“前沿动态”优先关注AI应用与功能变化，候选不足时扩展科技和产品热点。AI资讯使用 `kind=ai` 和 `aiApplication`；科技/产品新闻使用 `kind=news` 和 `newsTopic=technology|product`，须有可核验的实际发布日期。长期产品介绍继续归入产品发现，预告或预览须明确可用条件。

首页默认展示6条资讯，不限发布日期：先未读，同一阅读状态下最近7个北京时间自然日优先，再按AI、科技、产品及实际发布日期排序。往期内容可补位并标注“往期精选”，已读补位标记“已读”，收藏不隐藏，不感兴趣仍排除；“查看已读”不限日期，最多展示最近6条。阅读或收藏保持当前卡片，检查新简报后重选，划走后补位。保留真实发布日期，旧资料不改成今日发布；未收录足够候选时准确说明资料库缺口，不把已读或来源失败描述成没有新闻。

卡片采用双列3行，手机单列，标题、两行简介、主题、日期和阅读状态清晰可见。产品列表与推荐封面按比例铺满图片区并裁切，去除品牌彩色底；详情画廊继续完整显示原图，图片失败保留真实提示。

“全部前沿”提供完整资料库，支持主题、实际发布日期范围、已读状态和排序筛选，显示筛选后的数量。首页展示近期优先、日期不限的6条动态。列表封面仅显示简短图片标识；完整说明和原始来源放在详情画廊。手机主卡先展示标题和产品价值，再展示图片。

往期简报日期卡分别显示“未读”“已读”和当前选中状态。成功打开某期后记录其实际内容版本；同一期后来有内容更新时提示有更新，支持手动标为未读。简报已读表示该期已打开，不会把期内所有产品详情自动标为已看；两类阅读记录独立持久保存。

## 产品与资讯图片画廊

产品、设计和AI资讯详情使用同一画廊：缩略图、左右切换与图片数量，点击主图打开居中的大图查看器，可缩放、打开原图；桌面支持左右方向键和ESC关闭大图，手机支持左右滑动切图。说明与原始来源放在图片下方。单张图与无图内容继续兼容，图片失效时显示真实提示。

`IntelItem.images` 为可选数组，最多50张，每项为 `{url, caption, sourceUrl}`。旧 `image` 仍优先作为封面，同URL合并并使用画廊中的说明与来源；仅有 `images` 的内容直接使用第一张作封面。采集任务主动检查官网、文档、发布记录及官方仓库中的界面、流程与场景图，可靠资料丰富时争取5—12张不同内容图片，有更多价值时继续收集，不用重复图或logo凑数。

`/api/update-guide` 返回各条目的 `imageCount` 与 `missingImages` 辅助查漏；计数只代表已存URL，不代表外链已实时复检。为旧内容补图时通过 `/api/catalog` 提交合并后的完整记录，保留原有事实、来源和日期；不覆盖历史简报。完整采集口径见 [采集规则](docs/采集规则.md)。

## 阅读批注与笔记导出

产品、设计和资讯的详情正文支持原生选中文字后划线或写想法。点击划线可继续编辑，详情笔记入口查看当前内容的记录，“我的笔记”集中查阅与搜索。也可不选原文，直接记下一条想法。Markdown 与可打印 HTML 导出包含原文摘录、个人想法、产品来源、记录时间及历史简报版本；HTML 可在浏览器打印为 PDF。旧收藏备注自动归入可编辑笔记，保留内容、产品关联及原有时间；相同原文只导入一次，编辑或删除后不会被旧记录覆盖或重新出现。取消收藏仍保留笔记。收藏资料的 JSON 导出包含当前笔记。

笔记保存在 Vercel 所用的个人数据库，通过 `/api/annotations` 读写，采集服务不接收或覆盖个人笔记。每条摘录保存创建时的原文及上下文；资料更新后只在能够唯一匹配时重新定位，否则保留摘录供查阅，不把划线附到不确定的新内容上。修改使用版本检查，避免多个标签页静默覆盖；删除采用软删除并支持立即撤销。导出文件含个人内容，由用户自行保存。

未保存的想法自动暂存于当前浏览器，按用户、产品和历史日期隔离。关闭编辑器或刷新后，可从详情的“继续本机草稿”恢复，包括原先选中的摘录；保存或主动丢弃后移除草稿。草稿不会跨设备同步，也不算已保存笔记；本机存储不可用时明确提示。“我的笔记”可打开对应产品或定位原文，无法唯一匹配时保留摘录并说明。

## 每日内容更新

首页分别显示北京时间的“今天”、最新简报日期和当日是否已产出；查看历史时另列当前查看日期。“检查新简报”重新读取简报、阅读记录、收藏偏好、推荐和档案，明确区分已更新、暂无新增、当日尚未产出及读取失败。“核对 GitHub 数据”只更新仓库 Star，显示实际成功核对数，不启动内容采集，也不改变简报日期。`/api/feed` 的 `meta.freshness` 分开提供今天、最新简报和最近 Star 核对时间，内容状态以真实简报为准。

保留的 Sites 旧入口同样区分“检查新简报”和“核对 GitHub 数据”，并提供“打开新版工作台”入口。简报状态取自最近一期内容，Star 核对结果单独记录；没有当天简报时保留实际日期并明确提示，读取失败保留上次内容。点击检查只读取已采集的数据，不会自动启动全网研究。`npm test` 同时运行采集服务的日期与数据契约回归测试，避免旧入口再次出现错误的刷新提示。

采集不限内容发布日期：近期变化优先，仍有价值的成熟产品、历史案例与教程也可进入本期。简报日期表示实际研究编辑日期，卡片保留真实发布日期与首次发现时间；同一事件不因换日期重复推送。

统一策略见 [采集规则](docs/采集规则.md)，运行时真源为 `lib/collection-policy.ts`，通过 `/api/update-guide` 输出。Moonvy 用于设计灵感与产品发现；GitHub 增加 AI 创作产品与解决实际问题的完整方案，按产品价值、维护、使用门槛和证据筛选。微信公众号与博主来源重点关注“数字生命卡兹克”，择优提炼原创体验、可复现工作流和产品启发；文章种子与待核验状态写入统一规则，访问受限时如实记录，不将标题或摘要冒充已读正文。

导入使用事务与 ON CONFLICT DO NOTHING，可重放而不覆盖新数据；发现多个源用户时中止，要求明确身份映射。

## 内容与邮件边界

采集不限 AI：数字工具、实体商品、消费品、行业解决方案和设计均可入选。Star 仅为关注度快照；商业判断标为推断，保留原始来源及实际发布日期。历史简报不允许被后续内容覆盖。

邮件使用服务端 SMTP 配置：`SMTP_HOST`、`SMTP_PORT`、`SMTP_SECURE`、`SMTP_USER`、`SMTP_PASS` 和 `MAIL_FROM`。465 使用 SSL/TLS，587 强制 STARTTLS；保留证书校验。QQ 邮箱使用 SMTP 授权码，不能使用登录密码。真实配置只放私有环境，不入库；缺少配置时不能启用自动发送。

设置中可保存收件邮箱、自定义每日发送时间，并开启或关闭“定时发送”。默认每天北京时间 **20:00**；旧版没有实际调度的 `08:30` 兼容值仅迁移一次，之后尊重用户保存的时间。修改后点击保存生效，界面显示真实任务状态与下次时间；关闭后不再自动发送，手动测试与立即发送仍需用户主动操作。当天已经发送或结果不确定的简报，不因改时间、格式、开关或重新采集而再次发送。

邮件正文只展示一张热点海报，最多选取当期5条产品、设计与前沿信息，保留原始发布日期及预览/Beta等标记。海报使用随应用发布的中文字体离线生成 PNG，通过 CID 内嵌随邮件传输，不需要手机访问海外图床或登录工作台才能看正文。邮件客户端仍决定具体显示方式；可以保存内嵌图片。个人笔记、收藏与草稿不会进入海报。`/api/email/poster` 在原私人访问边界内提供今日海报预览，不创建或发送邮件。

定时发送使用 Vercel Workflow 的持久化等待，时间和任务状态保存在数据库；睡眠不依赖本机电脑或浏览器保持打开。到点只发送当天完整且非空的简报；内容未就绪则等待当天采集完成，不拿旧简报冒充当天热点。关闭或修改设置会让旧任务失效，发送前仍检查最新开关、时间与收件人。原有每日08:30采集及Codex只读提醒保持独立。调度可能因平台或邮件服务出现延迟，SMTP接收时间以投递记录为准。

本地 Workflow 状态位于 `.workflow-data/`，不入库；部署需要开启 Vercel 系统环境变量访问与 Fluid compute。普通 Vercel Hobby Cron 仅有小时级精度，因此本项目不通过固定 Cron 表模拟用户的分钟级设置。

`email_deliveries` 持久化冻结的收件人和内容，按用户、类型、日期或请求 ID 去重；并发请求只允许一次发送。同日补采不重复发信。SMTP 接收成功显示“发信服务已接收”，不代表已进入收件箱。网络中断或发送进程结果不明标为“结果待确认”，不会自动重发；应先查收或核对邮箱发信记录。发信失败不会回滚已经成功保存的简报。
