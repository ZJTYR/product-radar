# 拾光 · 产品情报工作台

面向产品经理的每日产品研究与设计灵感工作台。包括今日精选、产品与商业拆解、设计灵感、按账户隔离的收藏/分类/备注、往期完整快照、搜索与手机布局。

## 内容口径

- 采集覆盖各行各业：数字产品、实体商品、消费品、企业工具与行业解决方案；AI 是栏目，不是范围限制。
- 入选依据为 GitHub 高关注、可核验的市场表现、产品或设计灵感中的任一项，不要求每款产品都有仓库。按历史记录轮换行业与来源，避免长期只推 AI/SaaS。
- 市场数据写明原始来源、发布日期、统计期间与指标口径，厂商自述明确标注。公司业绩不当成单品销量；评论、榜单、缺货不直接等于热销。无销量依据时作为产品观察收录。
- 首期是实地核验的精选产品观察；不把成熟项目标成当日新发布。
- Star 为采集时点快照，关注度不代表收入或客户规模。
- 事实、厂商表述和产品分析分别展示，每条内容保留原始来源。
- 先用一句话说明产品做什么，再讲背景、痛点、具体使用示例、步骤与价值。数据、许可和来源放入可展开的资料区；没有真实图片时明确提示，不用字母占位冒充截图。
- 每日简报与长期选品库分开：首页提供最多 10 个 GitHub 高关注候选，按已核验关注度排序；它们是库内精选，不是全站榜单或当日新发布。
- 手动“更新数据”刷新公开 GitHub Star，不能替代每日研究编辑。

## 运行与数据

使用 Sites Vinext starter、Cloudflare Workers 和 D1。线上访问保持 owner-private，收藏与偏好按 Sites 提供的稳定用户ID隔离。手机与电脑使用同一账户访问，可共享收藏数据。

本地运行 `npm run dev -- --port 5187`。先生成并构建，再按 starter README 的 D1 步骤应用 `drizzle/` 中尚未应用的迁移。预览的本地登录只用于开发，不进入生产。

## 每日更新

发布后，Sites 关联云端任务读取 `/api/update-guide`，从官方公开来源研究，使用 `/api/ingest` 原子写入当日期刊与资料库。每期快照独立保存；收藏与备注不受内容更新影响。

`POST /api/catalog` 接收 `{items: IntelItem[]}`（1—50 条），按稳定 ID 更新长期产品库，不更改期刊快照、用户收藏或每日运行状态。`scenario` 和 `imageCaption` 为兼容旧内容的可选字段。需要修改当天简报表达时另行提交完整 `/api/ingest`；历史快照保持原样。

产品、设计和AI资讯统一支持可选 `images:[{url,caption,sourceUrl}]`（最多50张）。每天主动查找官网、文档、发布记录和官方仓库中的不同功能界面、流程与场景图，可靠资料丰富时争取5—12张，有更多有价值图片时继续补充，不凑数、不把logo当截图。逐图核验可访问性、MIME、实际尺寸与来源，说明区分真实界面、官方演示、宣传或示意图及已知版本。旧 `image`/`imageCaption` 继续作为兼容封面。正式Vercel工作台负责多图切换与大图查看，本站负责采集和同步字段。

`/api/update-guide` 在已有记录中提供 `imageCount` 与 `missingImages` 辅助补图；它们是已存URL计数，不代表外链实时可用性。先取得完整旧记录，合并原画廊与新图、核验并去重，通过 `/api/catalog` 提交完整IntelItem；保留稳定id、事实、来源和首次发现/实际发布日期，不覆盖历史简报。运行时统一规则为 `lib/collection-policy.ts`，版本2026-10-27.1。

后台服务访问必须通过 Sites 官方服务访问方式，凭据只在运行时获得，不放在代码、浏览器或任务提示中。`/api/ingest`、`/api/catalog`、`/api/system` 依赖 owner-private 访问边界，不能直接将本站改成公开。

## 邮件

界面可保存收件邮箱和期望时间。当前没有发信服务或自动投递实现，邮件开关保持不可启用。不得将保存偏好描述为已订阅或已发送。后续接入投递服务并完成真实投递核验后再启用。

## 验收

检查今日内容和来源、搜索、详情打开关闭、收藏/分类/备注刷新保留、手机端布局、历史快照和邮箱待配置状态。每天更新的任务创建结果与实际运行结果分别核对。
